User Interface:
Web UI styled like a speed test site (ui/frontend). The user picks how many traffic
windows to scan with a slider (fixed min and max), presses SCAN, and sees the summary
(records scanned, duration, malicious found, status). A Results tab lists previous scans.
A Flask backend (ui/backend) loads best_model.joblib, scores the records with the saved
threshold, and exposes /api/scan and /api/history.
For now the records come from the saved test set. Live traffic will replace
get_records() in ui/backend/data_source.py.

Database:
SQLite file (ui/backend/scans.db) with one table, scans, that stores every scan:
date, records, duration, malicious found, status, missed malware, false alarms, accuracy.
